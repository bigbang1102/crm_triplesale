ย้ายจาก Java/JSF มาเป็น Angular + API ใหม่

เซิร์ฟเวอร์ข้อมูล mockup ของทีม

สำเนา mockup ใช้ tools/mockup-server.mjs เป็น Datasource/Storage กลางที่ทั้งทีมใช้ร่วมกันผ่าน https (container แยก มี token ต่อคน) ข้อมูลของคนหนึ่งเห็นที่คนอื่นทันที มี Keycloak และ triplesales-api จำลองในตัวเพื่อทดสอบล็อกอินหลายบริษัท (npm run mockup:tenant) ข้อมูลตั้งต้นคือลูกค้า 180 ราย + โอกาสขาย 240 รายการ

triplesales-api (backend ใหม่)

  • รูปแบบ: modular monolith แพ็กเกจ com.triplesales.enterprise
  • โมดูล: account (session, สิทธิ์), organization, masterdata, notification, util (idempotency, เลขเอกสาร), common (audit, file storage, trace) และ pipeline = lead, prospect, opportunity, contact activity, schedule, dashboard, forecast, quotation
  • ฐานข้อมูล: PostgreSQL 17 + dbmate (migration 113 ไฟล์) · ไฟล์บน S3
  • สังเกตการณ์: Actuator + Prometheus + OpenTelemetry
  • กติกาข้อมูล: ทุก query กรองด้วยบริษัทจาก token ; record ที่มองไม่เห็นตอบ 404
  • สิทธิ์: action code (@RequiresAction) + ซ่อนฟิลด์รายตัว (field masking)
  • Deploy: GitLab CI → registry → job deploy-dev รัน migration ; profile local/dev/uat/prd ; secret อยู่ใน Vault
  • โหมดเร่ง: branch develop-urgent ทำงานแบบ "IMPACT fast mode" ติดป้าย FAST-DEBT + spec ใน docs/fast-specs/

ลำดับการล็อกอิน (แบบใหม่ ผ่าน Keycloak)

  1. กรอกรหัสกลุ่ม ตรวจด้วย GET /auth/groups/{code}
  2. Keycloak Authorization Code + PKCE (ชื่อผู้ใช้มี prefix ของกลุ่ม)
  3. POST /me/session ได้ข้อมูลผู้ใช้และรายชื่อบริษัท
  4. เลือกบริษัท PUT /me/session/company/{id} (เก็บฝั่ง server, ล็อกอินได้ที่เดียว)
  5. ทุก call แนบ Bearer อัตโนมัติ ; 401 = session จบ ; มี refresh token

Red ERP / POS

REDJAKA SYSTEM · เวอร์ชัน 2.3.0.0

ERP แบบเว็บที่รันบน WildFly 30 ขายเป็นหลายสายผลิตภัณฑ์จากโค้ดชุดเดียว: ERP, POS Gold (ร้านทอง + ออมทอง), POS Retail, Shopfloor, CRM หน้าจอเป็น JSP ที่ขับด้วย XML ต่อเอกสาร (~800 เอกสาร) รายงานใช้ JasperReports และเอกสารใหม่สร้างด้วยเครื่องมือ redTools จาก Excel

ซอร์ส vs ที่รันจริง

แก้โค้ดที่ wildfly2 แล้วคัดลอกไป deploy tree (red-erp-wildfly หรือ new-template) — ตัวที่ WildFly อ่านคือ deploy tree ไม่ใช่ wildfly2

แอปใน redjaka.ear

red.war (หน้าหลัก /red), EJB ของ kernel/workflow/security, jar ต่อเอกสาร ~1,400 ไฟล์, acedrilldown.war (REST สำหรับ drilldown)

ฐานข้อมูล MySQL

red2 (หลัก), goldcenter, btnccenter, plusconf, quickconf ผ่าน JNDI java:/REDDS ฯลฯ

ฟอร์ม · รายงาน · redTools ทำงานอย่างไร

ฟอร์มบันทึกรายการ (transaction)

  1. เมนู (ตาราง usermenu) เปิด /red/control/…
  2. MainServlet วาดหน้ากลาง wfgui3 ตาม <doc>-webinterface.xml
  3. การแสดงผลฟิลด์มาจากตาราง wfdisplay_* ; ป้ายข้อความอยู่ใน XML
  4. บันทึก → SavehandlerServlet → EJB ใน red-<doc>.jar → MySQL
  5. อนุมัติ/ลงบัญชีตาม conf/red/workflow/* ; พิมพ์ฟอร์มจาก form/<module>/*.jasper

รายงาน

  1. เมนูเปิด reportdefault/<MOD>/…/filter_*.jsp (หน้าเลือกเงื่อนไข)
  2. ดู/พิมพ์: post ไป /rpt/jasperReport เติม .jasper (SQL อยู่ใน jrxml) → PDF
  3. Excel: SQL จากตาราง wfdownloadexcel
  4. Drilldown: acedrilldown อ่าน SQL จาก wfdownloadexcel + wfdrilldownreport (ใน DB ไม่อยู่ใน version control)
ระวัง: SQL ของทางพิมพ์ (jrxml) กับทาง drilldown (DB) เป็นคนละที่ ต้องแก้ให้ตรงกันด้วยมือ ; แก้ jrxml แล้วต้อง compile เป็น .jasper ด้วย JasperReports 7.0.3 บน JDK 21 เท่านั้น (compile ด้วย JDK 25 หรือ JR 6 จะเปิดไม่ได้)

สร้างเอกสารใหม่ด้วย redTools

  1. BA เขียน layout spec → dev จัดลำดับฟิลด์ใน Excel usecase (red-erp-excel-gen)
  2. อัปโหลดเข้า redTools (Tomcat + MySQL ของตัวเอง) แล้วกด Generate
  3. ได้ Java → red-<doc>.jar, XML documenttype/businessdocument, webinterface.xml และแถวใน wfdisplay_*
  4. คัดลอกขึ้น WildFly UAT → redeploy/restart (XML ถูก cache ตอน deploy) → แปลข้อความ

Environment (ระบุแค่บทบาท)

  • เครื่อง dev: แก้ใน wildfly2 → คัดลอกไป deploy tree ในเครื่อง
  • UAT: Windows + WildFly 30 (deploy folder เป็น SVN working copy ด้วย) ; เข้าแบบอ่านอย่างเดียวผ่าน SSH
  • DB server: MySQL ; gen server: Tomcat + redTools (ต้องใช้ MySQL connector 5.1) ; เครื่อง JBoss 3 เก่า: Business Document Management
  • Production: แยกจาก UAT ; ยืนยันการ deploy ด้วย hash ของไฟล์และ log WFLYSRV0010 Deployed "redjaka.ear" ไม่ใช่เวลาแก้ไฟล์
