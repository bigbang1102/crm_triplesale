## วิธีใช้

- รัน spec ที่มีอยู่ : `npm test -- --include "src/app/features/leads/**/*.spec.ts"` (`npm test` = `ng test` ; ตาม CLAUDE.md) ; spec นอกโฟลเดอร์ Lead ที่เกี่ยวข้อง : `--include "src/app/core/mock/{waitlist,role-store,org-chart}.spec.ts"` (เพิ่ม `--include` ได้หลายครั้ง).
- กรณี **U** = เพิ่ม `it(...)` ใหม่ในไฟล์ที่ระบุ (ไม่ต้องเปิดเบราว์เซอร์) ; ผลที่คาดเขียนตามข้อกำหนดและตามสิ่งที่โค้ดทำจริง — ถ้าแตกต่างกัน ให้ถือว่ากรณีนั้นเจอข้อต่าง (บางกรณีติดธง (!)).
- กรณี **B** = เปิดหน้าด้วยบัญชีทดลอง (ตารางบัญชีด้านล่าง) ; ปุ่มทุกปุ่มผูกกับ `leads.access.ts` ที่เดียว จึงตรวจตรรกะสิทธิ์ด้วย unit แล้วมาดูแค่ว่าปุ่มโผล่/หายตรงกัน.
- รหัสในคอลัมน์ท้าย เช่น `ACC-7` ชี้ไปที่ "ดัชนี spec" ท้ายไฟล์ (ชื่อ `it(...)` ตามไฟล์จริง — ตรวจอ่านแล้ว ไม่ได้เดา).
- คำเตือนเรื่องความครอบ : ชื่อ `it` บางตัวพูดกว้างกว่าที่ assert จริง (เช่น MOCK-2 ชื่อบอกว่า "filter by … owner" แต่ assert เฉพาะตัวกรองแหล่งที่มา ไม่มี owner/ช่วงวันที่ ; MOCK-6 ชื่อบอกว่า "not a disqualified one" แต่ assert แค่สถานะไม่เปลี่ยน ไม่ได้ยืนยันว่าปฏิเสธบันทึก) — ตารางนี้นับตามสิ่งที่ assert จริง.

### หมายเหตุ
- ไฟล์ส่งออก (9 คอลัมน์ เริ่มด้วยวันที่สร้าง) ไม่ใช่รูปแบบ Template นำเข้า (5 คอลัมน์ เริ่มด้วยชื่อ) — ป้อนกลับเข้าไปไม่ได้ ตามที่ออกแบบ ; แถวหัวของไฟล์ส่งออกถูกอ่านเป็นแถวข้อมูล (นับเป็น "ข้อมูลไม่ครบ")
- เบอร์ "0000" แสดงเป็น `+66 0000` ในตารางตัวอย่างของหน้าต่างนำเข้า (นับเป็นไม่มีเบอร์ถูกต้อง — แค่การแสดงผล)
- ยังไม่ได้ทดสอบ: ดาวน์โหลดไฟล์จริงผ่านเบราว์เซอร์ + เปิดใน Excel ภาษาไทย · หน้าต่างเลือกไฟล์ของระบบ · ไฟล์ใกล้ 2 MB ที่มีหลายพันแถว (เวลาประมวลผล) · บัญชีสิทธิ์ต่างกัน (รอบนี้ใช้ demo อย่างเดียว) · ธีมมืด/ภาษาอังกฤษ
