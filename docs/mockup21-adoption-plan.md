## 2. สรุปการประเมิน

ใช้เป็น **สเปกและแหล่งตรรกะ** ได้ แต่ **ฝังตรงๆ ไม่ได้** เพราะ

1. โปรเจกต์ย้ายหน้าแบบ 1:1 จาก Java ผ่าน generator และ Dashboard/Report เป็นไฟล์ที่ถูกสร้าง ห้ามแก้ด้วยมือ — mockup เป็นการออกแบบใหม่ที่ไม่มีไฟล์ Java ต้นทาง
2. shell/สีต่างกัน: mockup ใช้แถบซ้ายสีเข้ม สีม่วง `#33205f` และชุดสี `--c1…c7`; โปรเจกต์ใช้ shell ที่วัดจาก Java, `--ts-primary: #35236a`, token `var(--ts-…)` และสีกราฟจาก `palettes.ts` (ห้ามใช้สีอื่น)
3. โค้ดคนละแบบ: โปรเจกต์เป็น Angular 21 (standalone, signals, OnPush, zoneless)
4. สิทธิ์คนละรูปแบบ: โปรเจกต์ใช้คีย์จาก `/me/roles` ผ่าน `PermissionService`; mockup ใช้ role 12 แบบ + สิทธิ์รายตำแหน่งงาน ซึ่ง `docs/analysis` ไม่มีบันทึกว่า backend รองรับ
5. ข้อมูลจริง: Dashboard เดิมดึงจาก `/dashboard/*` และ `/dashboardapi`; รายงานเดิมเป็นหน้ารายการเปิด PDF ขนาดเล็ก ส่วน mockup คำนวณและเจาะลงเองฝั่ง client

## 3. หลักการตลอดแผน

- **เป็นหน้าใหม่อยู่ข้างของเดิม** ไม่แตะ Dashboard/Report ที่ generator สร้าง ใช้ route ใหม่ (เช่น `/analytics`, `/reports-v2` — ตัดสินในเฟส 0)
- **ใช้ shell เดิมของโปรเจกต์** ไม่นำ shell/เมนูของ mockup มา; สีใช้ `var(--ts-…)` และ `palettes.ts` เท่านั้น; ทดสอบธีมมืดและปุ่ม A A A ทุกหน้า
- **ชั้น `features → shared → core`**: ตรรกะข้อมูลและสิทธิ์เป็นไฟล์ framework-free; HTTP อยู่ใน `*.api.ts`; เลือก backend ด้วย `mock ? mock : live(restDepsOf(injector))`
- ข้อความผ่าน `t('app.…')` ทั้ง th/en (mockup เป็นไทยล้วน); สิทธิ์ใช้ `ROLE.*` + `PermissionService` ไม่พิมพ์สตริง role เอง
- เบอร์โทรใช้ `PhoneFormat`; ปล่อยให้ `DomGuards` ทำงานตามปกติ

### เฟส 0 — ตัดสินใจและถามเจ้าของระบบ

1. mockup จะ **แทน** Dashboard/Report เดิม หรือ **อยู่คู่กัน** (แนะนำอยู่คู่กัน)
2. backend มี "ตำแหน่งงาน", role 12 แบบ และ API ตั้งสิทธิ์รายตำแหน่งหรือยัง — ถ้ายังไม่มี เฟส 6 ทำได้แค่ mock
3. ขอ BRD-SM-PIPELINE v0.1 และ BRD-SM-CHAT v0.2 (กฎ Visibility Tree และ Action Matrix มาจากสองฉบับนี้)
4. ฟิลด์ AMT / PROB / ECD / TGT / CAMP / CASE จะมีใน backend เมื่อไร
5. ขอบเขตรอบแรก — mockup แยกรายงานเฟส 2 ไว้แล้ว (`P2REP` 10 รายการ) ใช้เป็นเส้นแบ่งตั้งต้นได้
6. ยืนยันวัตถุประสงค์รายงานที่ติด "รอยืนยัน" 6 จุด (เช่น CRMG14 ชื่อซ้ำกับ CRMG12)

### เฟส 2 — ชั้นข้อมูลและตรรกะ

เรียงตามความพร้อมของข้อมูล: (1) ภาพรวม / Lead / Pipeline → (2) KPI / ปฏิทินงาน / ค้นหาข้อมูลลูกค้า → (3) ทีมขาย / กิจกรรม / แชท → (4) แท็บเฟส 2
